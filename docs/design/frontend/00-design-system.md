# デザインシステム基盤 — デザインプロンプト

## プロジェクト概要

Obsidianの学習ノートを知識ソースとして、LLMが理解度をチェックする個人学習支援ツールのフロントエンド。ユーザーがノートを書き→システムが取り込み→ロードマップを生成→クイズで理解度を検証→進捗を可視化、という学習ループを提供する。

## 全体のデザインコンセプト

### 目指す体験

このアプリは「夜の書斎で一人で学習に集中している」雰囲気を目指す。Obsidian本体のダークUIと隣り合わせで使うため、同系統のダークテーマで視覚的な断絶を生まない。派手な装飾やゲーミフィケーション要素は避け、**情報の視認性と操作の静けさ**を重視する。

### UX原則

1. **一画面一目的**: 各画面は明確な1つの目的を持つ。ダッシュボードは「今日何をするか決める」、ロードマップ詳細は「どの項目を学ぶか選ぶ」、クイズは「回答に集中する」
2. **進捗の可視化は控えめに**: スコアは常に見えるが、主張しすぎない。グレー→ローズ→アンバー→エメラルドの色遷移で自然に理解度が伝わる。数値を前面に出しすぎてプレッシャーを与えない
3. **遷移は最短経路**: ロードマップ→項目選択→クイズ開始が3クリック以内。学習のモチベーションが高い瞬間を逃さない
4. **中断と再開が自然**: セッションはいつでも中断でき、再開はワンクリック。「途中で止めた罪悪感」を生まないUI（ステータス表示は「中断」ではなく「進行中」）
5. **情報密度は高く、ノイズは低く**: 開発者ユーザーなので情報を隠さない。ただしビジュアルノイズ（過度なボーダー、影、アニメーション）は削る

## ターゲット環境

- **デバイス**: デスクトップファースト（Obsidianとの併用が前提）
- **最小幅**: 1024px（ラップトップ画面を想定）
- **モバイル対応**: 不要
- **言語**: 全UIラベルは日本語。データ内容（タイトル、フィードバック本文等）も日本語
- **ユーザー**: 単一ユーザー（認証画面は不要）

| スコア範囲 | レベル | ラベル | カラー | Tailwindクラス |

| 0–25 | not_started | 未着手 | グレー | `text-slate-400`, `bg-slate-700` |

## レイアウトシェル

全画面で共通のアプリケーションシェル。

### ビジュアルイメージ

│ ┌──────────┐ ┌──────────────────────────────────────┐  │
│ │ 🔮       │ │ パンくずリスト / ページタイトル        │  │
│ │ Obsidian │ │                                      │  │
│ │ Quiz     │ │                                      │  │
│ │          │ │       メインコンテンツエリア           │  │
│ │ ■ ダッシュ│ │       （スクロール可能）               │  │

│ │          │ │                                      │  │
│ └──────────┘ └──────────────────────────────────────┘  │
└────────────────────────────────────────────────────────┘

### UX意図

サイドバー＋メインコンテンツの2ペインレイアウトを採用する理由:

- **常にナビゲーションが見える**: 学習中に「次はフィードバック確認しよう」と思ったとき、サイドバーからワンクリックで移動できる。ヘッダーナビやハンバーガーメニューだと1ステップ多い
- **画面幅を最大限活用**: ロードマップのツリーやクイズの回答エリアは横幅が必要。サイドバーは240pxと控えめにし、残りをコンテンツに使う
- **折畳でさらに広く**: クイズ中など集中したい場面ではサイドバーを64pxのアイコンモードに折り畳み、回答エリアを最大化できる
- **フィードバックの未読バッジ**: 学習と無関係の画面にいても、新しいフィードバックが来たことに気づける。ただし通知ポップアップのような割り込みはしない

### サイドバー

- 左固定配置、折畳可能（アイコンのみモード）
- 上部: アプリタイトル「Obsidian Quiz」（折畳時はアイコンのみ）
- ナビゲーション項目:

| ラベル | アイコン | ルート | 備考 |
|:---|:---|:---|:---|
| ダッシュボード | LayoutDashboard | `/` | |
| ロードマップ | Map | `/roadmaps` | |
| フィードバック | MessageSquare | `/feedbacks` | 未読件数バッジを表示 |

- アクティブ状態: 現在のルートに対応する項目の背景をハイライト
- クイズ画面（`/sessions/*`）はサイドバーからの直接遷移なし（ロードマップ詳細から遷移）

### メインコンテンツエリア

- サイドバーの右側、残りの幅を占有
- 上部にパンくずリスト（Breadcrumb）
- コンテンツはスクロール可能（ScrollArea）
- パディング: p-6

## 共通UXパターン

### ローディング状態

- 初回ページ読み込み: Skeletonプレースホルダー（レイアウト構造を維持）
- アクション実行中: ボタンにスピナー + disabled状態
- バックグラウンド更新: 視覚的インジケータなし（楽観的更新）

### 空状態

- 中央配置のアイコン + 日本語メッセージ + CTAボタン
- 例: 「ロードマップがまだありません」+「新規作成」ボタン
- 背景はmutedカラー、テキストはmuted-foreground

### エラー状態

- 一過性エラー（API失敗等）: Toastで通知（右下、自動消去）
- フォームバリデーション: インラインエラーメッセージ（入力欄直下、destructiveカラー）
- 致命的読み込みエラー: フルページエラー表示 + 「再読み込み」ボタン

### スコア表示パターン

全画面で統一して使用するスコア表示コンポーネント。学習アプリのコア情報。

```
[87] 十分        ← 数値 + ラベルBadge（emeraldカラー）
████████░░ 87%   ← Progressバー（同色系）
```

- 数値: tabular-nums、font-semibold
- Badge: スコアカラーの背景 + テキスト
- Progressバー: 0-100%でスコアカラーと連動
- スコアが0の場合: 「—」表示、グレーカラー

**UX意図**: スコアは数値だけだと「良い/悪い」の判断に認知コストがかかる。カラーBadgeを併用することで、数値を読まなくても色で直感的に理解度が伝わる。4段階は「信号機＋グレー」のメタファーで、赤（不十分）→黄（部分的）→緑（十分）は万国共通の認知モデル。灰色（未着手）は「まだ何もしていない」ことを中立的に伝え、プレッシャーを与えない

### 日時表示パターン

| 条件 | 表示 | 例 |
|:---|:---|:---|
| 24時間以内 | 相対時間 | 「3時間前」「30分前」 |
| 7日以内 | 相対日 | 「昨日」「3日前」 |
| それ以降 | 絶対日時 | 「2026/05/20 14:30」 |
| 未実施 | プレースホルダー | 「—」 |

- Tooltipで常に絶対日時を表示

### 確認ダイアログパターン

- 削除等の破壊的操作: AlertDialog（destructiveバリアントのボタン）
- セッション再開確認: Dialog（選択肢ボタン）
- ボタンラベル例: 「削除する」「キャンセル」「再開する」「新規開始」

## API統合方針

- ベースURL: 環境変数 `VITE_API_BASE_URL` で設定
- TanStack Queryのカスタムhooksでデータ取得・キャッシュ管理
- エラーハンドリング: HTTPエラーをキャッチしてToast表示、クラッシュさせない
- 非同期ポーリング（ロードマップ生成ジョブ）: TanStack Queryの `refetchInterval` を使用
- 楽観的更新: フィードバック既読マーク等で使用

## アクセシビリティ要件

- 全インタラクティブ要素がキーボード操作可能
- アイコンのみのボタンにはaria-label必須
- 色だけに依存しない（常にテキストラベルまたはアイコンと併用）
- フォーカス可視スタイル（focus-visible）を全要素に適用
- フォーム入力には関連するlabel要素を紐付け
