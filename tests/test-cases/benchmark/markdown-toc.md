## テストケース（実装順）

### Phase 1: 最小骨格
1. 空文字列を渡すと空の目次が返る
2. 見出しのない本文のみのテキストを渡すと空の目次が返る
3. H1 が1つだけのテキストから、1エントリの目次が生成され、アンカースラッグが正しい

### Phase 2: コアロジック
4. H1, H2, H3 が混在するテキストから、レベルに応じた正しいインデント階層の目次が生成される
5. バッククォートのコードブロック内に `# comment` がある場合、その行は見出しとして認識されない
6. チルダのコードブロック内の行が見出しとして認識されない
7. 同じテキストの見出しが3つある場合、アンカーが `slug`, `slug-1`, `slug-2` となる
8. min_level=2, max_level=3 を指定すると、H1 と H4 以降が除外され、H2, H3 のみの目次が生成される

### Phase 3: エッジケース
9. 見出しテキスト内に `**bold**`, `` `code` ``, `[link](url)` が含まれる場合、装飾が除去されたプレーンテキストで目次エントリが生成される
10. `foo_bar_baz` のような単語内アンダースコアがイタリック除去されずにそのまま保持される
11. 日本語（ひらがな・カタカナ・漢字）を含む見出しのアンカースラッグが正しく生成される
12. H2 と H4 のみ（H3 が欠落）のテキストで、相対インデントが正しく計算される
13. ATX 見出しの末尾クロージング（`## Heading ##`）が除去されて、テキスト部分のみが目次に表示される
