## 機能概要

ノート取り込み時にLLMが内容を分析し、フィードバック（反映先通知・正確性チェック・改善提案）を生成してDBに蓄積する。ユーザーは好きなタイミングで未確認フィードバックを確認できる。

## 振る舞い

### 基本動作

取り込みパイプラインの最終ステップとして、チャンクの内容をLLM（Codex）に分析させ、IngestionFeedbackレコードを生成する。

### フィードバックの内容

1. **反映先通知**: このノートがどのロードマップ項目に関連するか（ロードマップが存在する場合）
2. **正確性チェック**: 内容に不正確な記述がないか
3. **改善提案**: 不足している観点や補足すべき内容の提案

### LLMに渡す情報

- 取り込まれたチャンクの内容
- 既存ロードマップの項目一覧（あれば）
- チャンクに付与されたタグ

### 具体例

入力チャンク:
```
TypeScriptのジェネリクスは型パラメータを使って
再利用可能なコードを書く仕組みです。
any型と違い、型安全性を保ちながら柔軟な関数を定義できます。
```

生成されるフィードバック:
```
title: "TypeScript > ジェネリクスに関するノート"
body: "このノートはロードマップ「TypeScript > 基礎 > ジェネリクスの基本構文と型パラメータ」に
関連しています。内容は正確ですが、ジェネリクスはクラスやインターフェースにも適用できる点が
記述されていません。追記すると理解がより深まります。"
source_path: "study/typescript/generics.md"
roadmap_item_id: (該当するRoadmapItemのID)
is_read: false
```

## 技術判断

- 取り込みバッチの最終ステップとして実行する理由: チャンク分割・タグ付与が完了した状態でフィードバックを生成するため、全ての情報が揃っている
- ファイル単位ではなくチャンク単位でフィードバックを生成する理由: チャンクごとに関連するロードマップ項目が異なる可能性がある。ただし同一ファイルのフィードバックは1つのIngestionFeedbackレコードにまとめる

## 境界条件

- ロードマップが存在しない → 反映先通知を省略。正確性チェックと改善提案のみ
- チャンクの内容が短すぎて分析できない → フィードバックを生成しない
- 変更ファイルの再取り込み → 新しいフィードバックを生成（旧フィードバックは残る）

## スコープ外

- フィードバックに基づくノートの自動修正
- フィードバックの優先度付け
- フィードバックの既読管理（feedback-listingが担当）

## 受け入れ基準

- [ ] 取り込み時にLLMがフィードバックを生成する
- [ ] フィードバックに反映先のロードマップ項目が含まれる（ロードマップが存在する場合）
- [ ] フィードバックに正確性チェックの結果が含まれる
- [ ] フィードバックに改善提案が含まれる
- [ ] 生成されたフィードバックがIngestionFeedbackテーブルに保存される
- [ ] is_readがfalseで保存される
