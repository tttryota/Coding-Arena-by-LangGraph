## 機能概要

ユーザーが選択したトピックに対して、LLMが学習ロードマップ（3階層: 大枠→中枠→具体）を一括生成する。非同期で実行され、完了後にユーザーが確認できる。

## 振る舞い

### 基本動作

トピック名を受け取り、LLM（Codex）に学習ロードマップの生成を依頼する。生成されたロードマップはRDB（SQLite）に永続化される。

### 大枠の構造（必須ルール）

大枠は全トピック共通で以下の2段階を固定する:

- **基礎**: 初学者が押さえるべき事項を網羅
- **応用**: 中上級者へのステップアップに必要なテクニック・知識・実務的知識

### LLMに委ねる部分

- 中枠の分類（トピックの性質に応じて自由に構成）
- 具体項目の内容
- 何を基礎、何を応用に分類するか
- 各項目の順序（前提知識の依存関係に従う）

### LLMへのプロンプト制約

- 大枠は「基礎」「応用」の2段階であること
- 前の項目が後の項目の前提知識になる順序であること
- 各具体項目は独立してクイズで理解度を確認できる粒度であること
- 各具体項目の確認ポイントは3〜5個に収めること。コードで表現できるポイントは知識+実践のセットで出題されるため、結果として6〜10問程度になる。超える場合は内容で分割し、タイトルに範囲を明示すること
- 各項目にはtitleとdescription（何を学ぶかの説明）を含めること

### 具体項目の粒度（ワンショット例をプロンプトに含める）

```
悪い例:
  title: "ジェネリクス"
  → 確認ポイントが多すぎる（基本構文、型制約、ユースケース、条件型連携...）

良い例:
  title: "ジェネリクスの基本構文と型パラメータ"
  title: "ジェネリクスの型制約とextends"
  title: "ジェネリクスとユーティリティ型の組み合わせ"
  → それぞれ確認ポイントが3〜5個に収まる
```

### LLMの出力形式

JSON形式で返させる:
```json
{
  "topic": "TypeScript",
  "items": [
    {
      "title": "基礎",
      "description": "初学者が押さえるべきTypeScriptの基本事項",
      "level": "major",
      "children": [
        {
          "title": "変数と型",
          "description": "TypeScriptの基本的な型システムと変数宣言",
          "level": "middle",
          "children": [
            {
              "title": "プリミティブ型",
              "description": "string, number, boolean等の基本型",
              "level": "detail"
            }
          ]
        }
      ]
    }
  ]
}
```

入力: トピック名 "TypeScript"

## 技術判断

- 大枠を基礎・応用の2段階に固定する理由: 全トピックで学習体験を統一する。「実践」は基礎・応用の中の実務的知識として包含する。何が基礎で何が応用かの判断はLLMに委ねる
- トピック名のみを入力とする理由: LLMの学習データに主要IT分野の知識体系は含まれている。ユーザーのノート内容はマッピング時に使用し、ロードマップ生成には不要
- JSON形式で出力させる理由: 構造化パースが容易。RDBへの永続化に直結する
- 非同期実行の理由: LLMの生成に時間がかかるため、ユーザーを待たせない

## 境界条件

- トピック名が曖昧（例: "プログラミング"） → LLMの判断に委ねる。結果が広すぎればユーザーが項目を削除・調整する
- LLMのJSON出力がパースできない → リトライする。3回失敗したらエラーを返す
- 同一トピックで2回目の生成 → 新しいロードマップとして別途作成する（既存は残す）

## スコープ外

- ロードマップの手動作成（LLM生成のみ）
- 生成時のユーザーとの対話的なやり取り（一括生成して後から修正）
- ロードマップ間の依存関係管理

## 受け入れ基準

- [ ] トピック名からLLMがロードマップを生成する
- [ ] 大枠が「基礎」「応用」の2段階で生成される
- [ ] 3階層（大枠→中枠→具体）で生成される
- [ ] 各項目にtitleとdescriptionが含まれる
- [ ] 項目の順序が前提知識の依存関係に従っている
- [ ] 非同期で実行される
- [ ] 生成結果がRDBに永続化される
