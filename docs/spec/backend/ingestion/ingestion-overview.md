## グループの責務

Obsidian Vaultからノートを定期的に取り込み、チャンク分割・タグ付与・Embedding生成を経てベクトルDBに格納するパイプライン。

`core/` パッケージに属する汎用基盤であり、学習支援固有のロジックに依存しない。タグ付与のプロンプトやチャンク分割の戦略は設定/ストラテジーパターンで外部から注入する。

## 含まれる機能

| # | 機能 | 概要 |
|---|------|------|
| A1 | ファイル差分検出 | 対象パス配下のファイルのmtime比較で新規/変更/削除を判定 |
| A2 | チャンク分割 | Markdownを見出し単位でチャンクに分割。見出しなしの場合はファイル全体を1チャンク |
| A3 | LLMタグ付与 | チャンクにLLM（Codex）でタグを自動付与。プロンプトはストラテジーで注入 |
| A4 | Embedding生成 | チャンクをmultilingual-e5-largeでベクトル化 |
| A5 | チャンクストア | ChromaDBへのチャンク+Embedding格納・更新・削除 |
| A8 | 定期バッチスケジューラ | 上記A1〜A5を10〜30分間隔で実行 |

## 処理フロー

```
定期バッチ起動（10〜30分間隔）
  │
  ▼ 同期（軽量）
A1: ファイル差分検出
  - 新規: 前回になかったファイル → 取り込み
  - 変更: mtimeが変わったファイル → チャンク丸ごと作り直し
  - 削除: なくなったファイル → 対応チャンク削除
  │
  ▼ 同期（CPU処理）
A2: チャンク分割
  │
  ▼ 非同期（API呼び出し）
A3: LLMタグ付与
  │
  ▼ 非同期（ローカル推論）
A4: Embedding生成
  │
  ▼ 同期（DB書き込み）
A5: チャンクストア（ChromaDB格納）
```

- バッチ全体をバックグラウンドジョブとして順次実行
- 変更ファイルはチャンク丸ごと作り直し（差分計算はしない）

## 外部依存

### このグループが利用するもの

| 依存先 | インターフェース | 用途 |
|--------|----------------|------|
| `core/llm/` | LLMクライアント | タグ付与のLLM呼び出し |
| `core/embedding/` | Embeddingクライアント | ベクトル生成 |
| `core/vectordb/` | ChromaDB操作 | チャンクの格納・削除 |

### このグループを利用するもの

| 利用元 | 用途 |
|--------|------|
| `domain/roadmap/` | 新規チャンクのロードマップマッピング（A6はroadmapドメインが担当） |
| `domain/analytics/` | 取り込みフィードバック生成（A7はanalyticsドメインが担当） |

## 前提制約

- 取り込み対象はMarkdown形式（`.md`）のみ
- 対象パスは設定で指定（例: Vault内の `/study`）
