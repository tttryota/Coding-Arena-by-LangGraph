## 機能概要

Obsidian Vaultの対象パス配下のMarkdownファイルを走査し、前回取り込み以降の変更（新規・変更・削除）を検出する。定期バッチの最初のステップとして、後続の取り込みパイプラインに処理対象を渡す。

## 振る舞い

### 基本動作

対象パス配下の全Markdownファイル（`.md`）を走査し、前回の走査結果と比較して差分を返す。

- **新規**: 前回の走査時に存在しなかったファイル
- **変更**: 前回の走査時からmtimeが変わったファイル
- **削除**: 前回の走査時に存在したが、今回存在しないファイル

### 走査結果の保持

各ファイルのパスとmtimeを記録し、次回の走査時に比較する。記録はRDB（SQLite）またはファイルとして永続化する。

### 具体例

前回の走査結果:
```
study/typescript/generics.md  mtime=2026-05-16T10:00:00
study/typescript/types.md     mtime=2026-05-15T09:00:00
study/docker/basics.md        mtime=2026-05-14T08:00:00
```

現在のファイル状態:
```
study/typescript/generics.md  mtime=2026-05-17T14:00:00  ← mtime変更
study/typescript/types.md     mtime=2026-05-15T09:00:00  ← 変更なし
study/typescript/async.md     mtime=2026-05-17T12:00:00  ← 新規
                                                          ← docker/basics.md は削除
```

出力:
```
新規: [study/typescript/async.md]
変更: [study/typescript/generics.md]
削除: [study/docker/basics.md]
```

## 技術判断

- mtime比較を採用する理由: ファイル内容のハッシュ比較より軽量。Obsidianは自動保存でmtimeが更新されるため、変更検出として十分
- 対象パスを設定で指定する理由: Vault全体ではなく学習ノートのみを対象とするため。また汎用基盤として他用途でも再利用可能にするため

## 境界条件

- 対象パスが存在しない → エラーを返す
- 対象パス配下にファイルがない → 空の差分（新規0・変更0・削除0）を返す
- 初回実行（前回の走査結果がない） → 全ファイルを「新規」として返す
- サブディレクトリ内のファイル → 再帰的に走査する
- `.md` 以外のファイル → 無視する
- シンボリックリンク → 無視する

## スコープ外

- リアルタイムのファイル監視（watchdog等）
- ファイル内容の差分検出（どの行が変わったか）
- ファイルのリネーム検出（旧ファイルの削除 + 新ファイルの新規として扱う）

## 受け入れ基準

- [ ] 新規ファイルが検出される
- [ ] mtimeが変わったファイルが変更として検出される
- [ ] 削除されたファイルが検出される
- [ ] mtimeが変わっていないファイルは差分に含まれない
- [ ] 対象は `.md` ファイルのみ
- [ ] サブディレクトリが再帰的に走査される
- [ ] 初回実行時は全ファイルが新規として返る
- [ ] 対象パスが設定で指定できる
