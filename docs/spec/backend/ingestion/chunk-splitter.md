## 機能概要

Markdownテキストを意味のある単位（チャンク）に分割する。RAGパイプラインの最初のステップとして、後続のタグ付与・Embedding生成・ベクトルDB格納の入力を作る。

## 振る舞い

### 基本動作

Markdownテキストを受け取り、見出し単位で分割したチャンクのリストを返す。

- H1（`#`）およびH2（`##`）を分割境界とする
- H3以下（`###` 〜 `######`）は親チャンクの一部として含める
- 見出しがないファイルはファイル全体を1チャンクとする
- 各チャンクには見出し階層の情報（headers）を付与する

### トークン上限による再分割

分割結果が512トークンを超えるチャンクは、段落（空行区切り）単位で再分割する。Embeddingモデル（multilingual-e5-large）の入力上限が512トークンであり、超過部分はベクトルに反映されないため（ADR-003参照）。

### 特殊な要素の扱い

- **コードブロック**（`` ``` `` で囲まれた範囲）: コードブロックの途中では分割しない。コードブロック内の見出し記法は見出しとして扱わない
- **フロントマター**（YAML）: 付与しない前提のため無視する。存在する場合はチャンクに含めない
- **Obsidian内部リンク**（`[[リンク先]]`）: テキストとしてそのまま含める。特別な処理はしない

### 具体例

入力:
```markdown
# TypeScript入門

TypeScriptの基本を学ぶ。

## 型システム

TypeScriptの型システムについて。

### ジェネリクス

ジェネリクスの説明...

### 型推論

型推論の説明...

## 非同期処理

async/awaitについて。
```

出力: 3チャンク
- チャンク0: 「TypeScriptの基本を学ぶ。」（headers: "TypeScript入門"）
- チャンク1: 「TypeScriptの型システムについて。ジェネリクスの説明... 型推論の説明...」（headers: "TypeScript入門 > 型システム"）
- チャンク2: 「async/awaitについて。」（headers: "TypeScript入門 > 非同期処理"）

## 技術判断

- H1〜H2を分割境界とする理由: 学習ノートの典型的な構造ではH1がテーマ、H2がサブトピックを表す。H3以下は説明の一部であることが多い
- 512トークン上限: Embeddingモデルの入力上限に起因（ADR-003参照）
- 再分割は段落単位: 文の途中で分割すると意味が壊れるため、空行を境界とする

## 境界条件

- 空ファイル → 空リストを返す
- 見出しのみで本文がないセクション → 空のチャンクは生成しない（スキップ）
- H1が複数ある → それぞれが独立したチャンクの起点になる
- 段落再分割しても512トークンに収まらない（巨大な段落）→ 512トークンで強制分割する
- コードブロックが閉じられていない → ファイル末尾までをコードブロックとして扱う

## スコープ外

- Setext形式の見出し（`===` / `---` による見出し）の対応
- Markdown以外のファイル形式
- 画像や添付ファイルの処理
- チャンクの意味的な品質評価

## 受け入れ基準

- [ ] H1およびH2の見出しで分割される
- [ ] H3以下は親チャンクに含まれる
- [ ] 見出しなしのファイルは1チャンクとして返る
- [ ] 空ファイルは空リストを返す
- [ ] 各チャンクに見出し階層（headers）が付与される
- [ ] 512トークンを超えるチャンクが段落単位で再分割される
- [ ] コードブロック内の見出し記法が見出しとして扱われない
- [ ] コードブロックの途中で分割されない
- [ ] フロントマターがチャンクに含まれない
