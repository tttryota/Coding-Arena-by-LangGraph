## 機能概要

確認ポイントリストと過去の問答履歴を踏まえて、具体的な問題文を都度生成し、ユーザーに提示する。

## 振る舞い

### 基本動作

次に確認すべきポイントと過去の問答を受け取り、文脈に沿った問題文を生成する。

- 問題セット設計ノードの確認ポイントリストから、次の未確認ポイントを選択
- 過去の問答の文脈を踏まえて自然な問題文を生成
- 出題形式（知識 / 実践）に応じた問い方をする
- 問題文と一緒に回答形式（`answer_type`: "textarea" / "code"）を返す。フロント側がこの値でUIを自動切り替え

### 問題文の生成ルール

- 前の問答で使った用語や例を引き継ぐ（シミュレーションで問3が文脈を無視して失敗した教訓）
- 知識問題: 概念の説明や理由を問う
- 実践問題: 実際に使う場面を想定した問題にする。構文の確認ではなく「それを使ってどう問題を解くか」を問う
  - 入出力の要件と具体例を明示する
  - 本質でない部分（関数名等）はあらかじめ提示し、実装に集中させる。ただしシグネチャ（型定義）は提示しない。ユーザー自身が考える
  - ユーザーの脳のリソースを問題の本質に集中させる

### セッション再開時

QuizAnswer履歴が渡された場合、続きの確認ポイントから出題を再開する。

### 具体例

知識問題の例:

確認ポイント: 「明示的型指定と型推論の違い」
過去の問答: 問2で `function identity<T>(arg: T): T` の `<T>` について回答済み

生成される問題文:
> 「先ほどのidentity関数について、`identity<string>("hello")` と型引数を省略して `identity("hello")` と書くこともできます。なぜ省略できるのか、またどちらの書き方が望ましいと思いますか？」

実践問題の例:

確認ポイント: 「ジェネリクスを使った関数定義」

生成される問題文:
> 「配列と判定関数を受け取り、条件に合う要素だけを返すジェネリック関数 filterBy を実装してください。
> 例: `filterBy([1, 2, 3, 4], n => n > 2)` → `[3, 4]`
> 　　 `filterBy(["a", "bb", "ccc"], s => s.length > 1)` → `["bb", "ccc"]`」

実践問題で提示するもの: 関数名、文章での要件説明、具体的な使用例
実践問題で提示しないもの: シグネチャ（型定義は自分で考える）、実装

### UIとユーザーアクション

フロントエンドは2つの入力エリアを持つ:
- **回答フォーム**: answer_typeに応じてtextarea or コードエディタが自動切り替え。送信すると常に回答として扱われる
- **チャット欄**: 質問や解説依頼を入力する常設の入力欄

### 出題内容への質問

ユーザーはチャット欄から出題内容について質問できる（要件の曖昧さの解消）。LangGraph内の入力分類ノードが質問か解説依頼かを判断し、質問の場合はLLMがステート（出題内容・過去の問答）を踏まえて応答する。質問は評価に影響しない。

チャット欄からのアクション:
- **質問** → 入力分類ノード → LLMが応答 → 同じ問題に戻る（評価に影響しない）
- **解説依頼** → 入力分類ノード → 解説ノードへ

回答フォームからのアクション:
- **送信** → 常に回答として評価+ルーティングノードへ

## 技術判断

- 問題文を都度生成する理由: 事前に全問題文を作ると前の問答との文脈が断絶する。LLMが毎回文脈を踏まえて生成することで自然な対話になる

## 境界条件

- 全確認ポイントが確認済み → 出題せず、セッション完了に進む
- 深掘りが発生した場合 → ルーティングから追加の確認ポイントを受け取り、それに基づいて出題
- 20問を超過した場合 → 重要な未確認ポイントがあれば最小限の追加で収束。なければ完了に進む

## スコープ外

- 問題の難易度調整
- 問題のテンプレート化
- 画像や図を含む問題の生成

## 受け入れ基準

- [ ] 確認ポイントに基づいた問題文が生成される
- [ ] 過去の問答の文脈を踏まえた自然な問題文になる
- [ ] 知識問題と実践問題で適切に問い方が変わる
- [ ] 問題文と一緒にanswer_type（textarea / code）が返される
- [ ] 実践問題の要件が文章で示され、シグネチャはコードで提示されない
- [ ] チャット欄からの質問にLLMが応答できる
- [ ] 質問への応答が評価に影響しない
- [ ] 全確認ポイント完了後に出題が停止する
- [ ] セッション再開時に続きから出題される
