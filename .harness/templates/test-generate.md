## 手順
1. まず主対象のテストファイル `{{targetTestFile}}` を開く
2. 必要なら対応する実装ファイル `{{targetImplementationFile}}` だけ確認する
3. 主対象のテストファイルを placeholder から具体的なテストコードへ更新する
4. repo 全体の充足確認や既存テストの監査だけで終わらない

## 制約
- 承認済みテストケースを唯一の生成対象として扱う
- 仕様書は期待値と用語の補足にのみ使い、承認済みテストケースにない独自テストは追加しない
- 原則として 1 つの承認済みテストケースにつき 1 つの test intent を割り当てる
- 既存テストへアサート追加で済む内容を、別の test 関数へ不要分割しない
- テストをまとめて構造化する（テストフレームワークの慣習に従う）
- テスト命名はテスト対象・条件・期待結果が分かる形式にする
- 各テストに何を検証し何を期待するかを示すコメントまたは説明を書く
- 1テスト1関心事
- モックは外部依存のみ
- 実装コードの探索は import、公開インターフェース確認、言語設定確認に必要な最小限に留める
- lint/type で明らかに怒られる書き方を避ける
- `try`-`except`-`pass` や例外の握り潰しで不変性や失敗ケースを検証しない
