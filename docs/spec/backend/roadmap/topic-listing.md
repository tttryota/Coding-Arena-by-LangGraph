## 機能概要

ロードマップ生成のためのトピック候補をユーザーに提示する。プリセット・ノートから自動生成されたタグ・自由入力の3つのソースからトピック候補を提供する。

## 振る舞い

### 基本動作

トピック候補の一覧を返す。各トピックにはソース情報（プリセット / ノート由来）と、関連するノートの件数が含まれる。

### トピック候補の3つのソース

1. **プリセット**: IT分野の主要トピックをシードデータとしてDBに事前登録。言語・フレームワーク・インフラ・概念等
2. **ノートから自動生成**: taggerが新しいタグを生成した際に追加される
3. **自由入力**: ユーザーが任意のトピック名を入力できる。プリセットにないニッチなトピック用

### 具体例

レスポンス:
```
[
  { "name": "TypeScript", "source": "preset", "note_count": 12 },
  { "name": "Docker",     "source": "preset", "note_count": 3 },
  { "name": "React",      "source": "preset", "note_count": 0 },
  { "name": "LangGraph",  "source": "note",   "note_count": 5 },
  ...
]
```

自由入力: ユーザーが「Terraform」と入力 → そのままロードマップ生成に渡せる。トピックとしてDBに登録される。

## 技術判断

- プリセットを用意する理由: 自由入力だけだと表記ゆれが起きる。また「何を入力すればいいかわからない」問題を防ぐ
- プリセットの粒度: 「ロードマップを作る意味がある単位」。初期はメジャーなトピックのみ、後から追加可能
- note_countを含める理由: ノートがあるトピックは「既に学習中」であることを示す手がかりになる

## 境界条件

- プリセットもノート由来タグもない（初回起動時） → プリセットのみが返る
- 自由入力のトピック名が既存トピックと重複 → 既存トピックを返す（新規登録しない）
- 自由入力が空文字 → エラーを返す

## スコープ外

- プリセットの管理画面（追加・削除はDB直接操作またはシードデータ更新）
- トピックの階層構造（タグはフラット）
- トピックの統合・リネーム機能

## 受け入れ基準

- [ ] プリセットのトピック候補が一覧で返る
- [ ] ノートから自動生成されたタグがトピック候補に含まれる
- [ ] 各トピックに関連ノート件数が付与される
- [ ] ユーザーが自由にトピック名を入力でき、ロードマップ生成に渡せる
- [ ] 自由入力したトピックがDBに登録される
- [ ] 既存トピックと重複する自由入力は新規登録されない
