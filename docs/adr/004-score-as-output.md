# ADR-004: スコアは判断の出力として算出する

**ステータス:** 承認
**日付:** 2026-05-18

## コンテキスト

クイズの回答評価やロードマップ項目の進捗算出において、score（0〜100）をどのタイミングで算出するかを決定する必要がある。scoreを先に算出して閾値で判断するか、定性的な判断を先に行ってscoreを後付けするかの2つのアプローチがある。

## 決定

scoreは判断の出力として算出する。LLMがまず定性的な判断（理解度の評価、次のアクションの決定）を行い、その判断を数値化したものとしてscoreを導出する。

## 根拠

- LLMの思考として自然な順序は「回答を読む → 理解度を判断する → 数値化する」であり、scoreから逆算して判断するのは不自然
- scoreを先に算出すると、閾値ベースの機械的な判断になり、回答の文脈（概念はわかるがコードが書けない等）を反映できない
- 回答評価（answer-evaluation）と進捗算出（progress-update）の両方に適用される設計原則として一貫性がある
- scoreは人間がダッシュボードで進捗を確認するためのインターフェースであり、システムの判断基準ではない

## 適用箇所

- **回答評価ノード**: 理解度の判定と根拠 → 次のアクション判断 → score → フィードバック
- **出題項目評価ノード**: 全問答の総合コメント → score
- **深掘り判断**: scoreの閾値ではなく、回答内容に基づくLLMの判断
