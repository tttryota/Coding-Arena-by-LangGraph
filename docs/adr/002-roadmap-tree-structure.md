# ADR-002: ロードマップの階層構造に隣接リスト（parent_id）方式を採用

**ステータス:** 承認
**日付:** 2026-05-17

## コンテキスト

ロードマップは大枠→中枠→具体の3階層構造を持つ。RDBでツリー構造を表現する方法として以下の選択肢がある：

1. 隣接リスト（parent_id方式）
2. 経路列挙（path方式）
3. 入れ子集合（nested set方式）
4. クロージャテーブル

## 決定

隣接リスト（parent_id方式）を採用する。

## 根拠

- 階層が固定3段（大枠/中枠/具体）で深くならない
- 1ロードマップあたりの項目数はせいぜい数十〜100程度
- `roadmap_id` で全件取得してアプリ側でツリー構築すれば十分な規模
- 再帰クエリが必要になるほどの複雑さにはならない
- 項目の移動（parent_id変更）が最もシンプル

## 却下した選択肢

- **経路列挙（path方式）**: LIKE検索で配下を一発取得できるが、項目移動時にpathの書き換えが全配下に波及する。今回の規模ではメリットが薄い
- **入れ子集合 / クロージャテーブル**: 大規模ツリーには有効だが、3段固定の構造にはオーバーエンジニアリング
