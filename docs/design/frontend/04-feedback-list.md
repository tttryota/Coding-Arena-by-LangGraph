# フィードバック一覧 — デザインプロンプト

## 前提

- デザインシステム: `00-design-system.md` に従う
- この画面は他の画面と独立しており、フィルタ付きリストパターンを確立する
- サイドバーのフィードバックナビゲーション項目に表示する未読バッジと連動する

## 画面概要

- **ルート**: `/feedbacks`
- **目的**: Obsidianノートの取り込み時にLLMが生成したフィードバック（正確性チェック・改善提案・反映先通知）を一覧表示する
- **ユーザーストーリー**: ユーザーがノートを書いた後、システムが生成したフィードバックを確認し、ノートの改善やロードマップとの関連を把握する

## ビジュアルイメージ & UX意図

### ページの見た目

メールの受信トレイに似た構成。上部にフィルタ、その下にフィードバックカードが縦に並ぶ。未読のカードはタイトル左に青いドットが付き、既読のカードはやや薄く表示される。

```

│                                                              │
│  [開始日: ____] 〜 [終了日: ____]     表示: [すべて ▼]       │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ ● generics.md の取り込みフィードバック          3時間前 │  │
│  │   src/notes/typescript/generics.md                      │  │
│  │                                                        │  │
│  │   反映先ロードマップ: TypeScript / 型システム / ジェネリクス│  │
│  │   正確性チェック: ジェネリクスの説明は概ね正確です       │  │
│  │   が、制約（extends）の記述に不足があります...           │  │
│  │                                                        │  │
│  │   [関連ロードマップ]              [既読にする]          │  │
│  └────────────────────────────────────────────────────────┘  │

│  │   改善提案:                                             │  │
│  │   - useEffectの依存配列について具体例を追加する          │  │
│  │   - カスタムフックの命名規則を補足する...               │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### UX設計のポイント

- **受信トレイのメタファー**: メールを読む感覚で扱える。未読は目立ち、既読は引っ込む。開発者にとって自然なインターフェース
- **未読ドット（●）は青**: スコアカラー（赤/黄/緑）と混同しない色を使う。「未読=アクション待ち」を独立した視覚チャネルで伝える
- **既読カードは消えない、薄くなるだけ**: 既読にした後も一覧に残る。後から見返したいときにフィルタで「既読のみ」に切り替えれば探せる
- **フィルタは即時反映**: Selectの値変更で即座にリストが更新される。「適用」ボタンを押す手間がない。日付入力のみ300msのdebounceを入れてAPIコール数を抑制
- **bodyの構造化表示**: バックエンドが生成するフィードバック本文は「反映先ロードマップ」「正確性チェック」「改善提案」の3セクションで構成される。これらをただのテキストではなく、セクションごとに視覚的に区別して表示する。反映先は太字、改善提案はリスト表示
- **本文は2-3行にtruncate**: 長いフィードバックを全文表示するとリストのスキャン性が落ちる。クリックで全文展開/折畳できる
- **「関連ロードマップ」Badge**: フィードバックがロードマップ項目に紐づいている場合のみ表示。クリックするとそのロードマップに飛べる。「このフィードバックはどの学習に関係するのか」がすぐわかる
- **サイドバーの未読バッジと連動**: 既読にするとサイドバーの数字がリアルタイムに減る。「処理した」フィードバックが明確になる

## API依存

### `GET /ingestion/feedbacks`

フィードバック一覧を取得する（フィルタ付き）。

```typescript
// クエリパラメータ
{
  date_from?: string   // ISO 8601（inclusive）例: "2026-05-20T00:00:00+09:00"
  date_to?: string     // ISO 8601（inclusive）
  read_status: "all" | "unread" | "read"  // デフォルト: "all"
}

// レスポンス
{
  items: FeedbackListItem[]
  total_count: number
}

type FeedbackListItem = {
  id: string               // UUID
  source_path: string      // ノートのファイルパス
  roadmap_item_id: string | null  // 関連するロードマップ項目のID
  title: string            // "{source_path} の取り込みフィードバック"
  body: string             // 構造化テキスト（反映先ロードマップ、正確性チェック、改善提案）
  is_read: boolean
  created_at: string       // ISO 8601
  read_at: string | null   // ISO 8601
}
```

### `PUT /ingestion/feedbacks/{feedback_id}/read`

フィードバックを既読にする。

```typescript
// レスポンス: FeedbackListItem（更新後の状態）
```

## コンポーネント構成

### ページヘッダー

| 要素 | 内容 |
|:---|:---|
| パンくず | `フィードバック` |
| タイトル | 「フィードバック」（text-xl, font-semibold） |
| 件数 | `total_count` + 「件」（text-sm, muted-foreground） |

### フィルタバー（FeedbackFilters）

| 要素 | 仕様 |
|:---|:---|
| 日付範囲 | 開始日Input（type="date"） + 「〜」 + 終了日Input（type="date"） |
| 表示フィルタ | Select（すべて / 未読のみ / 既読のみ） |
| フィルタ適用 | 値変更時に即座に再フェッチ（明示的な適用ボタンなし） |
| リセット | 「リセット」ボタン（ghost, small）— フィルタが初期値でない場合のみ表示 |

### フィードバックカード（FeedbackCard）

各フィードバック項目を表示するCard。

| 要素 | 仕様 |
|:---|:---|
| 未読インジケータ | 未読: タイトル左に青いドット（●） / 既読: なし |
| タイトル | `title`（font-medium）。未読はforeground、既読はmuted-foreground |
| ソースパス | `source_path`（text-xs, font-mono, muted-foreground） |
| 本文 | `body`のプレビュー（2-3行にtruncate）。クリックで全文展開 |
| 作成日時 | `created_at`の相対日時表示（text-xs, muted-foreground、右上配置） |
| 関連ロードマップ | `roadmap_item_id` が存在する場合のみ表示。Badge「関連ロードマップ」（クリックで該当ロードマップへ遷移） |
| 既読ボタン | 未読の場合のみ表示。「既読にする」（ghost, small） |
| 既読スタイル | 既読カードはopacity-70で表示を抑える |

#### body のフォーマット

バックエンドが生成する `body` は以下の構造化テキスト:

```
[反映先ロードマップ: TypeScript/型システム/ジェネリクス]
正確性チェック: ジェネリクスの説明は概ね正確ですが、制約（extends）の記述に不足があります。
改善提案:
- 制約付きジェネリクスの具体例を追加する
- ユーティリティ型との関連を補足する
```

- 各セクション（反映先、正確性チェック、改善提案）を視覚的に区別して表示
- 反映先ロードマップ行は太字
- 改善提案のリスト項目はインデント付きリスト表示

## インタラクション

| 操作 | 結果 |
|:---|:---|
| フィルタ値変更 | 即座にAPI再フェッチ（debounce不要、Selectなので） |
| 日付入力変更 | 300msのdebounce後にAPI再フェッチ |
| カードのbodyクリック | 本文の全文展開/折畳トグル |
| 「既読にする」クリック | `PUT /feedbacks/{id}/read` → 楽観的にUIを更新（ドット消去 + スタイル変更） |
| 「関連ロードマップ」Badge クリック | `/roadmaps/{roadmapId}` へ遷移（roadmap_item_idからroadmap_idを解決） |
| 「リセット」クリック | フィルタを初期値（date_from=null, date_to=null, read_status="all"）に戻す |

## 状態管理

### TanStack Query

| フック | クエリキー | 用途 |
|:---|:---|:---|
| `useFeedbacks(filters)` | `["feedbacks", filters]` | フィードバック一覧取得（filtersが変わるたびに再フェッチ） |
| `useMarkAsRead()` | — | mutation: 既読マーク（楽観的更新: キャッシュ内のis_readを即座にtrue化） |
| `useUnreadCount()` | `["feedbacks", "unreadCount"]` | サイドバーの未読バッジ用（全画面で使用） |

### Zustand

| store | 用途 |
|:---|:---|
| `useFeedbackFilters` | フィルタ状態の管理（URLクエリパラメータとの同期は任意） |

```typescript
{
  dateFrom: string | null
  dateTo: string | null
  readStatus: "all" | "unread" | "read"
  reset: () => void
}
```

## サイドバー未読バッジとの連動

- サイドバーの「フィードバック」ナビゲーション項目に未読件数のBadgeを表示する
- `useUnreadCount()` フックは `GET /ingestion/feedbacks?read_status=unread` の `total_count` を取得
- 既読マーク時に `useUnreadCount` のキャッシュも無効化（自動再フェッチ）
- バッジ表示: 件数が0の場合は非表示、1-99は数値、100以上は「99+」
