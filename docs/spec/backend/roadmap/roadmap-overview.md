## グループの責務

学習トピックのロードマップ（大枠→中枠→具体）の生成・管理・更新を担う。ユーザーに学習の全体像とゴールを提示し、ノートのカバー状況やクイズ結果による進捗を可視化する。

`roadmap/` パッケージに属する学習支援固有のドメイン。

## 含まれる機能

| # | 機能 | 概要 |
|---|------|------|
| B1 | トピック一覧取得 | タグをDBから集約してトピック候補を返す |
| B2 | ロードマップ生成 | トピックを元にLLMで大枠→中枠→具体を一括生成 |
| B3 | ロードマップ永続化 | 生成したロードマップをRDB（SQLite）にフラットレコードで保存 |
| B4 | ロードマップ項目再生成 | ユーザー指定の項目をLLMで再生成 |
| B5 | ロードマップ取得 | ロードマップの階層構造を返す（進捗状況付き） |
| B6 | ロードマップ改善提案蓄積 | セッション結果からの改善提案をDBに保存 |
| A6 | ロードマップマッピング | 新規チャンクを既存ロードマップ項目に紐付け |

## 処理フロー

### ロードマップ生成フロー

```
1. ユーザーがトピック一覧を取得（B1: タグ集約API）
2. トピックを選択
3. LLMがロードマップを非同期で全生成（B2: 大枠→中枠→具体を一括）
4. 既存チャンクを各項目にマッピング（A6: カバー済み/未着手を判定）
5. ロードマップをRDBに永続化（B3）
```

### ロードマップ更新フロー

```
ユーザー起点の項目再生成（B4）
  → 指定された項目をLLMで再生成
  → 配下の項目も含めて差し替え

新規ノート取り込み時（A6）
  → 既存項目へのマッピングのみ（構造は変えない）

クイズセッション終了時（B6）
  → 改善提案（細分化・前提知識追加）をDBに蓄積
  → ユーザーが確認・承認/却下
```

## ロードマップのデータモデル（概念）

ロードマップはRDBにフラットなレコードとして保持する。

- 各項目は階層（大枠/中枠/具体）を持つ
- 進捗は具体項目のみが持つ（insufficient / partial / sufficient）
- 中枠・大枠の進捗は配下の具体項目から算出する
- ロードマップは初回で具体レベルまで全生成し、ユーザーに全体像とゴールを示す

## 外部依存

### このグループが利用するもの

| 依存先 | インターフェース | 用途 |
|--------|----------------|------|
| `core/llm/` | LLMクライアント | ロードマップ生成・再生成・改善提案 |
| `core/vectordb/` | ChromaDB操作 | チャンクのマッピング時にタグ情報を取得 |
| `core/rag/` | RAG検索 | チャンクとロードマップ項目の類似度マッチング |
| `infrastructure/rdb/` | SQLite操作 | ロードマップの永続化 |

### このグループを利用するもの

| 利用元 | 用途 |
|--------|------|
| `quiz/` | 出題範囲の参照、進捗の反映 |
| `domain/analytics/` | 進捗集計、弱点分析 |

## 具体仕様書の一覧

| ファイル | 対象機能 |
|---------|---------|
| `topic-listing.md` | B1: トピック一覧取得（プリセット + ノート由来 + 自由入力） |

- roadmap-item-regeneration（LLMによる再生成）→ CRUD操作で代替
- roadmap-mapping（チャンクとの紐付け）→ RAGで都度検索すれば十分
