## 機能概要

チャンクの内容をLLMに分析させ、大分類レベルのトピックタグを自動付与する。タグはトピック一覧の候補提案やロードマップの絞り込みに使用される。

## 振る舞い

### 基本動作

チャンクのテキストを受け取り、大分類レベルのトピックタグのリストを返す。

- タグは学習分野の大分類（例: "TypeScript", "Docker", "ネットワーク", "データベース"）
- 1チャンクに複数タグが付く場合がある（例: "TypeScript"と"React"の両方に関連するチャンク）
- 既存タグ一覧をプロンプトに含め、同じ概念に対して異なるタグが付くことを防ぐ（例: "TS"と"TypeScript"の混在を避ける）

### タグ付与のプロンプト

プロンプトはストラテジーパターンで外部から注入する。`core/` の汎用性を保ち、学習支援以外の用途でも異なるタグ付け戦略を適用可能にする。

### 具体例

入力チャンク:
```
TypeScriptのジェネリクスは型パラメータを使って
再利用可能な型安全なコードを書く仕組みです。
```

既存タグ一覧: ["TypeScript", "Docker", "ネットワーク"]

出力: ["TypeScript"]

入力チャンク:
```
ReactコンポーネントでTypeScriptのPropsを型定義する方法。
useStateのジェネリクス指定について。
```

既存タグ一覧: ["TypeScript", "Docker", "React"]

出力: ["TypeScript", "React"]

## 技術判断

- 大分類レベルのみとする理由: 細分類（例: "ジェネリクス"）はロードマップが担う。タグの用途はトピック候補提案とロードマップの絞り込みであり、大分類で十分
- ストラテジーパターンでプロンプトを注入する理由: `core/ingestion/` は汎用基盤として他用途にも再利用可能にするため、タグ付けのロジックを外部から差し替え可能にする
- 既存タグ一覧をプロンプトに含める理由: LLMが自由に生成すると表記ゆれが発生する。既存タグを参照させることで一貫性を保つ

## 境界条件

- 既存タグ一覧が空（初回取り込み） → LLMが新規タグを自由に生成する
- チャンクの内容が曖昧で分類困難 → LLMの判断に委ねる。タグなし（空リスト）も許容する
- 既存タグに該当しない新しい分野 → LLMが新規タグを生成する

## スコープ外

- タグの階層構造（親子関係）
- タグの手動編集・削除
- 難易度タグや学習段階タグの付与
- タグの統合・リネーム機能

## 受け入れ基準

- [ ] チャンクに大分類レベルのトピックタグが付与される
- [ ] 既存タグ一覧がプロンプトに含まれ、表記ゆれが抑制される
- [ ] 1チャンクに複数タグが付与されうる
- [ ] 既存タグに該当しない場合、新規タグが生成される
- [ ] タグ付与のプロンプトが外部から注入可能である
