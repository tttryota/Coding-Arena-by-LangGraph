## 機能概要

Markdown テキストから見出しを抽出し、目次（Table of Contents）を生成する。

ハーネスの動作検証用ベンチマーク機能であり、プロジェクト本体の機能ではない。
検証完了後に削除する前提のため、他の機能との依存関係は持たない。

モジュールの配置先は `backend/benchmark/markdown_toc.py` とする。

## 振る舞い

### 基本動作

Markdown テキストを受け取り、ATX 形式の見出し（`#` 〜 `######`）を認識して目次を生成する。

目次の各行は `- [見出しテキスト](#アンカー)` 形式の Markdown リストとして出力する。
見出しレベルに応じてインデント（スペース2つ × 深さ）を付与する。
インデントの深さは相対的に計算する。出現する最小の見出しレベルを基準（深さ0）とし、
それより深いレベルはレベル差に応じてインデントする。
例: H2 と H4 のみの場合、H2 が深さ0、H4 が深さ2 となる。

呼び出し時に min_level と max_level を指定でき、対象とする見出しレベルの範囲を制限できる。
デフォルトは min_level=1, max_level=3。範囲外の見出しは目次に含めない。

目次の生成結果として、構造化された見出し一覧と、レンダリング済みの Markdown テキストの両方を返す。

### 見出しの認識ルール

- 行頭の `#` の連続数でレベルを判定する（1〜6）
- `#` の直後に1つ以上のスペースが必要（`#見出し` は見出しとして認識しない）
- コードブロック（トリプルバッククォートで囲まれた領域）内の行は見出しとして認識しない
- 見出しテキスト内の Markdown 装飾は除去してプレーンテキスト化する:
  - `**bold**` / `__bold__` → `bold`
  - `` `code` `` → `code`
  - `[link text](url)` → `link text`
  - `*italic*` / `_italic_` → `italic`

### アンカースラッグの生成ルール

GitHub 互換の方式を採用する:

1. テキストを小文字に変換する
2. 半角スペースをハイフン `-` に置換する
3. 英数字、ハイフン、アンダースコア、日本語（ひらがな・カタカナ・漢字）以外の文字を除去する
4. 連続するハイフンを1つにまとめる
5. 先頭と末尾のハイフンを除去する

同じアンカーが複数生成される場合、2つ目以降に `-1`, `-2`, ... を付番する。

## 技術判断

- **GitHub 風スラッグを採用**: Obsidian / GitHub / GitLab 等の主要 Markdown 環境と互換性を持たせるため。独自方式はリンク切れの原因になる。
- **ATX 見出しのみ対応**: Setext 形式（`===` / `---` アンダーライン方式）は Obsidian での利用頻度が低く、2行にまたがるパースの複雑度に見合わない。
- **日本語をスラッグに残す**: GitHub の実際の挙動に合わせる。日本語見出しのアンカーリンクが機能するために必要。
- **外部ライブラリ不使用**: ベンチマーク目的のため、標準ライブラリのみで実装する。

## 境界条件

- 空文字列を渡した場合: 空の目次を返す（エラーにしない）。利用側でのガード不要にするため。
- 見出しが1つもない場合: 空の目次を返す。
- コードブロックのみのテキスト: 見出しなしとして空の目次を返す。
- 閉じられていないコードブロック: 開始行以降を全てコードブロック内として扱う。ユーザーの意図として「まだ書きかけ」が最も多く、見出し誤認識よりも安全。
- 見出しレベルが飛んでいる場合（H2 の次に H4）: レベル差をそのままインデント差に反映する。自動補正はしない。
- min_level > max_level の場合: 空の目次を返す。
- `#` が7つ以上の行: 見出しとして認識しない（Markdown の仕様に準拠）。

## スコープ外

- Setext 形式の見出し対応
- HTML 見出し（`<h1>` 等）の認識
- 目次のナンバリング（`1.1`, `1.2` 形式）
- ファイル I/O（入力は文字列のみ）
- 既存の目次の検出・置換

## 受け入れ基準

- [ ] 空のテキストを渡すと空の目次が返る
- [ ] 見出しのないテキストを渡すと空の目次が返る

- [ ] 複数レベルの見出しが正しいインデント階層で出力される
- [ ] コードブロック内の `#` 行は見出しとして認識されない
- [ ] 同名の見出しに `-1`, `-2` の付番がされる
- [ ] min_level / max_level で対象レベルをフィルタできる
- [ ] 見出し内の Markdown 装飾が除去される
- [ ] 日本語を含む見出しのスラッグが正しく生成される
- [ ] 見出しレベルが飛んでいる場合のインデントが正しい
- [ ] ruff check がゼロ違反
- [ ] mypy --strict がゼロエラー
