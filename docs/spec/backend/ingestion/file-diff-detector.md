# 概要

- Obsidian Vault 配下の Markdown ノート取り込みにおいて、前回スキャン以降に処理が必要なファイルだけを抽出する。
- 利用者・呼び出し元は ingestion の定期バッチスケジューラおよび手動実行ユースケースを想定する。
- 前提条件は、呼び出し元が対象ディレクトリの絶対パスまたはそれと同等に解決可能なパスを渡し、永続化先は `FileDiffSnapshotStore` インターフェース越しに利用可能であること。

# 入出力

- 入力:
  - `target_path: str | Path`
    - 再帰走査を開始する対象ディレクトリ。
    - 存在する実ディレクトリでなければならない。
- 出力:
  - `FileDiffResult`
    - `target_path: str`
      - スキャン対象ディレクトリの正規化済みパス。
    - `new_files: list[str]`
      - 前回スキャン時に存在せず、今回存在する `.md` ファイルの相対パス一覧。
    - `updated_files: list[str]`
      - 前回スキャン時にも存在し、保存済み mtime と今回の mtime が一致しない `.md` ファイルの相対パス一覧。
    - `deleted_files: list[str]`
      - 前回スキャン時には存在し、今回存在しない `.md` ファイルの相対パス一覧。
    - `new_count: int`
    - `updated_count: int`
    - `deleted_count: int`
  - 返却するパスはすべて `target_path` からの相対パスとし、区切り文字は `/` に正規化する。
  - `new_files`、`updated_files`、`deleted_files` はそれぞれ辞書順昇順で返す。
  - 件数フィールドは各一覧の要素数と一致する。
- エラー:
  送出する例外の型名と発生条件を定義する。
  例外型はテストで使用されるため、型名を具体的に指定すること。
  実装詳細ではなく、呼び出し元との契約として記述する。
  - `TargetPathNotFoundError`: `target_path` が存在しない。
  - `InvalidTargetPathError`: `target_path` がディレクトリではない、または `target_path` 自体がシンボリックリンクである。
  - `TargetPathAccessError`: `target_path` またはその配下の走査・stat 取得に必要なアクセス権がなく、完全なスキャン結果を確定できない。
  - `ScanStatePersistenceError`: 前回スキャン結果の読み込みまたは今回スキャン結果の保存に失敗した。

# 主要ルール

1. 対象ファイル抽出:
   - 条件:
     - `target_path` 配下を再帰的に走査する。
     - 対象は拡張子が完全一致で `.md` の通常ファイルのみとする。
   - 振る舞い:
     - サブディレクトリを含めて走査し、`.md` 以外のファイルは比較対象に含めない。
     - `README.MD`、`.markdown`、ディレクトリ自体は対象外とする。
2. シンボリックリンク無視:
   - 条件:
     - 走査中にシンボリックリンクであるファイルまたはディレクトリを検出した場合。
   - 振る舞い:
     - シンボリックリンクのファイルは差分判定対象に含めない。
     - シンボリックリンクのディレクトリ配下には再帰しない。
3. 差分判定:
   - 条件:
     - 前回スキャン結果として、同一 `target_path` に紐づくスナップショットが存在する場合。
   - 振る舞い:
     - 前回に存在せず今回存在する相対パスは `new_files` に分類する。
     - 前回にも今回にも存在し、保存済み mtime と今回の mtime が異なる相対パスは `updated_files` に分類する。
     - 前回に存在し今回存在しない相対パスは `deleted_files` に分類する。
     - 前回にも今回にも存在し、mtime が一致する相対パスは返却しない。
4. 初回実行:
   - 条件:
     - 同一 `target_path` に対する前回スナップショットが存在しない場合。
   - 振る舞い:
     - 今回検出したすべての対象ファイルを `new_files` に分類する。
     - `updated_files` と `deleted_files` は空にする。
5. スナップショット永続化:
   - 条件:
     - スキャンが正常に完了した場合。
   - 振る舞い:
     - 今回検出した対象ファイルの相対パスと mtime の組を、同一 `target_path` に対応する最新スナップショットとして永続化する。
     - 永続化は `FileDiffSnapshotStore` インターフェース越しに行い、保存形式が RDB かファイルかは問わない。
6. 結果の決定性:
   - 条件:
     - 同一の入力ディレクトリ状態と同一の前回スナップショットで複数回実行した場合。
   - 振る舞い:
     - 返却される 3 つの一覧と件数は毎回同一でなければならない。
     - 返却パスの表記揺れ、順序揺れ、重複を許容しない。

# 境界条件

- ケース:
  - `target_path` が存在しない。
  - 振る舞い:
    - `TargetPathNotFoundError` を送出し、差分結果を返さない。
  - 理由:
    - 呼び出し元が設定不備を検知し、後続パイプラインを実行しないため。
- ケース:
  - 対象ディレクトリに `.md` ファイルが 1 件もなく、前回スナップショットも存在しない、または前回スナップショットも空である。
  - 振る舞い:
    - 空の差分 `(0, 0, 0)` を返し、空スナップショットを保存する。
  - 理由:
    - 取り込み対象がないだけであり、異常ではないため。
- ケース:
  - 前回スナップショットには `.md` ファイルが存在したが、今回の走査結果では `.md` ファイルが 0 件である。
  - 振る舞い:
    - 前回スナップショットに含まれていた全相対パスを `deleted_files` として返す。
  - 理由:
    - 最後の 1 件まで削除されたケースでも削除検知を失わないため。
- ケース:
  - 通常ファイル `topic.md` とシンボリックリンク `alias.md` が同じディレクトリに存在する。
  - 振る舞い:
    - `topic.md` のみ比較対象に含め、`alias.md` は完全に無視する。
  - 理由:
    - 同一実体の重複取り込みと予期しない走査範囲拡大を防ぐため。
- ケース:
  - ファイル内容は変わっているが mtime が前回保存値と一致している。
  - 振る舞い:
    - 変更なしとして扱い、`updated_files` に含めない。
  - 理由:
    - この機能の変更判定キーは mtime のみであり、内容ハッシュ比較は行わないため。
- ルール間の相互作用:
  複数ルールが同時に適用される場合は、`対象ファイル抽出` と `シンボリックリンク無視` を先に適用して現在スナップショット候補を確定し、その後 `初回実行` または `差分判定` を適用する。空ディレクトリ判定は差分判定の前提を補足する境界条件であり、前回スナップショットに削除対象がある場合は `差分判定` を優先して削除として返す。

# 非機能・制約

- 性能:
  - ファイル内容は読まず、ディレクトリエントリ列挙と stat 取得だけで完結する。
  - 計算量は対象ディレクトリ配下のエントリ数に対して線形であること。
- 可観測性:
  - 呼び出し元が記録できるよう、少なくとも `target_path`、`new_count`、`updated_count`、`deleted_count`、処理時間をログまたはメトリクスとして取得可能であること。
- 外部依存:
  - ローカルファイルシステム。
  - 前回スナップショットの読み書きを行う `FileDiffSnapshotStore` インターフェース。

# 技術判断

品質に直結する技術選定や実装方針がある場合は、その判断と理由を書く。

- 判断:
  - 比較対象の mtime はナノ秒精度の整数値を使用し、永続化時にも同じ精度を保持する。
  - 理由:
    - 浮動小数の丸め差で偽陽性・偽陰性が出ることを避け、テストを決定的にするため。
- 判断:
  - 永続化するファイルキーは `target_path` からの相対パスに統一し、区切り文字は `/` に正規化する。
  - 理由:
    - 保存先が RDB でもファイルでも OS 差分を吸収でき、出力契約も安定するため。
- 判断:
  - 変更判定に内容ハッシュではなく mtime のみを用いる。
  - 理由:
    - 要件に一致し、スキャンを軽量に保つため。

# スコープ外

この機能では扱わないこと、別 issue / 別機能で扱うことを明示する。

- 対応しないこと:
  - Markdown 内容の差分比較、内容ハッシュ計算。
  - `.md` 以外のファイル形式の監視。
  - ファイル変更イベントのリアルタイム監視。
  - 検出した差分に対するチャンク削除・再生成など後続処理の実行。

# 受け入れ基準

検証可能な条件をチェックリスト形式で書く。実装手段ではなく、満たされるべき事実を書く。

- [ ] 初回実行時、対象ディレクトリ配下の `.md` 通常ファイルがすべて `new_files` として返る
- [ ] 2 回目以降の実行時、前回保存済み mtime と比較して新規・変更・削除が正しく分類される
- [ ] `.md` 以外のファイルおよびシンボリックリンクは差分判定対象に含まれない
- [ ] サブディレクトリ配下の `.md` ファイルも再帰的に検出される
- [ ] 対象ディレクトリが存在しない場合は `TargetPathNotFoundError` が送出される
- [ ] 対象 `.md` ファイルが存在しない場合、削除対象がなければ空の差分 `(0, 0, 0)` が返る
- [ ] 前回スナップショットから全 `.md` ファイルが消えた場合、それらが `deleted_files` として返る
- [ ] 差分結果の各一覧は相対パスの辞書順昇順で返り、件数フィールドと整合する
- [ ] 正常終了時、今回の走査結果が次回比較用スナップショットとして永続化される

# テスト観点メモ

各主要ルールに対して最低1つ、各境界条件に対して最低1つの観点を列挙する。
受け入れ基準の各項目が少なくとも1つの観点でカバーされていることを確認する。

- 正常系:
  - 初回実行で 2 件の `.md` ファイルがすべて新規として返ること
  - 前回スナップショットありで、新規 1 件・更新 1 件・削除 1 件が同時に返ること
  - サブディレクトリ 2 階層以上の `.md` ファイルが再帰的に検出されること
  - `.md` 以外のファイルが混在していても結果に含まれないこと
  - 差分一覧が辞書順昇順で返り、件数が一覧長と一致すること
- 境界系:
  - 空ディレクトリの初回実行で空差分が返ること
  - 前回 1 件存在し、今回 0 件になった場合に削除 1 件として返ること
  - シンボリックリンクのファイルが `.md` 名でも無視されること
  - シンボリックリンクのディレクトリ配下にある `.md` が走査されないこと
  - mtime が同一で内容だけ変わったケースを変更なしとして扱うこと
- 異常系:
  - `target_path` が存在しない場合に `TargetPathNotFoundError` が送出されること
  - `target_path` が通常ファイルまたはシンボリックリンクの場合に `InvalidTargetPathError` が送出されること
  - 走査途中でアクセス権不足のディレクトリまたはファイルに遭遇した場合に `TargetPathAccessError` が送出されること
  - スナップショット読み込み失敗時と保存失敗時の双方で `ScanStatePersistenceError` が送出されること
