## 機能概要

Markdown テキストから見出しを抽出し、目次（Table of Contents）を生成する。

ハーネスの動作検証用ベンチマーク機能であり、プロジェクト本体の機能ではない。
検証完了後に削除する前提のため、他の機能との依存関係は持たない。

モジュールの配置先は `backend/benchmark/markdown_toc.py` とする。

## 振る舞い

### 基本動作

Markdown テキストを受け取り、ATX 形式の見出し（`#` 〜 `######`）を認識して目次を生成する。

目次の各行は `- [見出しテキスト](#アンカー)` 形式の Markdown リストとして出力する。
見出しレベルに応じてインデント（スペース2つ × 深さ）を付与する。
インデントの深さは相対的に計算する。出現する最小の見出しレベルを基準（深さ0）とし、
それより深いレベルはレベル差に応じてインデントする。
例: H2 と H4 のみの場合、H2 が深さ0、H4 が深さ2 となる。

呼び出し時に min_level と max_level を指定でき、対象とする見出しレベルの範囲を制限できる。
デフォルトは min_level=1, max_level=3。範囲外の見出しは目次に含めない。

目次の生成結果として、構造化された見出し一覧と、レンダリング済みの Markdown テキストの両方を返す。

### 見出しの認識ルール

- 行頭の `#` の連続数でレベルを判定する（1〜6）
- `#` の直後に1つ以上のスペースが必要（`#見出し` は見出しとして認識しない）
- `#` が7つ以上の行は見出しとして認識しない（Markdown 仕様準拠）
- コードブロック内の行は見出しとして認識しない（詳細は「コードブロックの認識」を参照）
- 見出し行の先頭にスペースがある場合は見出しとして認識しない（行頭が `#` であることを要求する）
- ATX 見出しの末尾クロージング（`## Heading ##`）は除去する。末尾の連続 `#` とその前のスペースを取り除く

### コードブロックの認識

- バッククォート（`` ` ``）3つ以上の連続で開始し、同じ文字の同数以上の連続で閉じる
- チルダ（`~`）3つ以上の連続も同様にコードブロックとして認識する
- バッククォートフェンスはチルダフェンスでは閉じない（逆も同様）
- 開きフェンスより短い閉じフェンスではコードブロックは終了しない（例: 4つで開いたら3つでは閉じない）
- 閉じられていないコードブロックは、開始行以降を全てコードブロック内として扱う

### Markdown 装飾の除去

見出しテキスト内の以下の装飾を除去してプレーンテキスト化する:

- `**bold**` → `bold`
- `__bold__` → `bold`（ただし単語内の `__` はボールド記法として扱わない。`foo__bar__baz` はそのまま）
- `` `code` `` → `code`
- `[link text](url)` → `link text`
- `*italic*` → `italic`
- `_italic_` → `italic`（ただし単語内の `_` はイタリック記法として扱わない。`foo_bar_baz` はそのまま）
- バックスラッシュエスケープは考慮しない（`\*text\*` の `\` は除去対象外。そのまま残る）
- 装飾記号 `*` / `**` が装飾ではなくリテラルとして使われている場合（`2 * 3`）の判別はしない。正規表現で最短マッチした範囲を除去する

### アンカースラッグの生成ルール

GitHub 互換の簡易方式を採用する:

1. テキストを小文字に変換する
2. 半角スペースをハイフン `-` に置換する
3. 以下の文字のみ残し、それ以外を除去する: 英小文字 `a-z`、数字 `0-9`、ハイフン `-`、アンダースコア `_`、日本語（ひらがな `\u3040-\u309f`、カタカナ `\u30a0-\u30ff`、漢字 `\u4e00-\u9fff`）
4. 連続するハイフンを1つにまとめる
5. 先頭と末尾のハイフンを除去する
6. 結果が空文字列になった場合はスラッグを空文字列とする（目次リンクは `(#)` となる）

重複アンカーの付番は、min_level / max_level でフィルタする前の全見出しに対して行う。フィルタ後に付番すると、除外された見出しとの重複が解決されず GitHub の実際の挙動と乖離するため。

### 具体例

入力:
```
# はじめに

本文テキスト

## インストール

手順の説明

## 使い方

### 基本的な使い方

### 応用例

## はじめに
```

min_level=1, max_level=3 での目次出力:
```
- [はじめに](#はじめに)
  - [インストール](#インストール)
  - [使い方](#使い方)
    - [基本的な使い方](#基本的な使い方)
    - [応用例](#応用例)
  - [はじめに](#はじめに-1)
```

## 技術判断

- **GitHub 風スラッグの簡易実装を採用**: 完全な GitHub 互換（全 Unicode カテゴリの処理）ではなく、英数字・日本語・ハイフン・アンダースコアのみを許可する簡易方式とする。フランス語のアクセント文字（`é` 等）やアラビア文字などは除去される。ベンチマーク目的であり、国際化対応は不要。
- **ATX 見出しのみ対応**: Setext 形式（`===` / `---` アンダーライン方式）はパース複雑度に見合わない。ベンチマーク目的のため最小限の対応とする。
- **日本語をスラッグに残す**: GitHub の実際の挙動に合わせる。
- **外部ライブラリ不使用**: ベンチマーク目的のため、標準ライブラリのみで実装する。
- **Markdown 装飾除去は正規表現の最短マッチで実装**: ネストした装飾（`***bold italic***`）や複雑なケースの完全な解析は行わない。正規表現で実用上十分な範囲をカバーする。
- **バックスラッシュエスケープは非対応**: CommonMark のエスケープ規則の完全実装はベンチマークの範囲を超える。
- **戻り値のデータ構造は frozen（不変）とする**: 目次の生成結果は値オブジェクトであり、生成後に変更する理由がない。不変にすることで意図しない状態変更を防ぐ。

## 境界条件

- 空文字列を渡した場合: 空の目次を返す（エラーにしない）。利用側でのガード不要にするため。
- 見出しが1つもない場合: 空の目次を返す。
- コードブロックのみのテキスト: 見出しなしとして空の目次を返す。
- 閉じられていないコードブロック: 開始行以降を全てコードブロック内として扱う。
- 見出しレベルが飛んでいる場合（H2 の次に H4）: レベル差をそのままインデント差に反映する。自動補正はしない。
- min_level > max_level の場合: 空の目次を返す（エラーにしない）。呼び出し側の便宜のため。
- 見出し行の先頭にスペースがある場合: 見出しとして認識しない。
- `foo_bar_baz` のような単語内アンダースコア: イタリック記法として扱わず、そのまま保持する。
- `2 * 3` のような非装飾の `*`: 正規表現の最短マッチにより `* 3` 部分が除去される可能性がある。これは既知の制限であり、ベンチマーク目的では許容する。
- スラッグが空文字列になる見出し（`## !!!`）: 空文字列のままとする。目次リンクは `(#)` となる。
- URL 内に `)` を含むリンク（`[text](https://example.com/foo_(bar))`）: 最初の `)` でリンクが終了したと判定される。これは正規表現ベースの制限であり、ベンチマーク目的では許容する。

## スコープ外

以下は本機能では対応しない。理由を併記する。

- **Setext 形式の見出し**: 2行にまたがるパースが必要で複雑度が高い。ベンチマーク目的では ATX のみで十分。
- **HTML 見出し（`<h1>` 等）**: HTML パーサーが必要。Markdown 処理の範囲を超える。
- **目次のナンバリング（`1.1`, `1.2` 形式）**: 本機能の目的はリンク付き目次の生成であり、ナンバリングは別機能。
- **ファイル I/O**: 入力は文字列のみとする。ファイル読み込みは呼び出し側の責務。
- **既存の目次の検出・置換**: 目次の生成と文書内への挿入は別の責務。
- **CommonMark のバックスラッシュエスケープ**: エスケープ規則の完全実装はパーサーの複雑度を大幅に上げる。ベンチマーク目的では不要。
- **全 Unicode カテゴリのスラッグ対応**: アクセント文字やアラビア文字等の処理。国際化はベンチマーク目的では不要。
- **インデント付きコードフェンス（先頭1-3スペース）**: CommonMark では許容されるが、実用上ほぼ使われない。パース複雑度に見合わない。

## 受け入れ基準

- [ ] 空のテキストを渡すと空の目次が返る
- [ ] 見出しのないテキストを渡すと空の目次が返る
- [ ] 単一の見出しから正しい目次が生成される
- [ ] 複数レベルの見出しが正しいインデント階層で出力される
- [ ] バッククォートのコードブロック内の `#` 行は見出しとして認識されない
- [ ] チルダのコードブロック内の `#` 行は見出しとして認識されない
- [ ] 同名の見出しに `-1`, `-2` の付番がされる
- [ ] min_level / max_level で対象レベルをフィルタできる
- [ ] 見出し内の `**bold**` と `` `code` `` と `[link](url)` が除去される
- [ ] `foo_bar_baz` の単語内アンダースコアがイタリック除去されずに保持される
- [ ] 日本語を含む見出しのスラッグが正しく生成される
- [ ] 見出しレベルが飛んでいる場合のインデントが正しい
- [ ] ATX 末尾クロージング（`## Heading ##`）が除去される
- [ ] ruff check がゼロ違反
- [ ] mypy --strict がゼロエラー
