## 機能概要

ロードマップをツリー構造で返す。各項目のスコア（進捗）を含め、フロントエンドがロードマップの全体像と進捗状況を表示するためのデータを提供する。

## 振る舞い

### 基本動作

roadmap_idを受け取り、そのロードマップの全項目をツリー構造で返す。

- roadmap_idで全RoadmapItemレコードを取得
- parent_id関係からツリーを構築
- 各項目にscoreを含める
- 中枠・大枠のスコアは配下のdetail項目から算出する（DBには保持していない）

### ロードマップ一覧取得

ユーザーが作成した全ロードマップの一覧を返す。各ロードマップのトピック名と全体の進捗率を含める。

### スコアの集約

- detail項目: DBに保持されたscoreをそのまま返す
- middle項目: 配下のdetail項目のscoreの平均
- major項目: 配下のmiddle項目のスコア（= 配下全detailの平均）の平均

### 具体例

リクエスト: `GET /roadmaps/{roadmap_id}`

レスポンス:
```json
{
  "id": "aaa",
  "topic": "TypeScript",
  "overall_score": 35,
  "items": [
    {
      "id": "001",
      "title": "基礎",
      "level": "major",
      "score": 50,
      "children": [
        {
          "id": "002",
          "title": "変数と型",
          "level": "middle",
          "score": 75,
          "children": [
            { "id": "003", "title": "プリミティブ型", "level": "detail", "score": 90, "last_quiz_at": "2026-05-15T10:00:00" },
            { "id": "004", "title": "配列とタプル", "level": "detail", "score": 60, "last_quiz_at": "2026-05-16T14:00:00" }
          ]
        }
      ]
    }
  ]
}
```

## 技術判断

- アプリケーション側でツリー構築する理由: parent_id方式のため、全件取得してメモリ上で組み立てる。固定3段・小規模なので十分な性能
- 中枠・大枠のスコアを都度算出する理由: detail項目のscoreが更新されるたびに上位を再計算するよりシンプル。規模が小さいので性能問題にならない

## 境界条件

- ロードマップが存在しない → 404エラー
- 項目が0件のロードマップ → 空のitemsで返す
- detail項目が全てscore=0（未着手） → 中枠・大枠のスコアも0
- detail項目にscoreが混在（0, 50, 100） → 平均を算出

## スコープ外

- ロードマップのフィルタ検索（トピック名での検索等）
- ページネーション（個人用ツールで項目数が小規模のため不要）
- スコアの加重平均や重み付け（単純平均を使用）

## 受け入れ基準

- [ ] roadmap_idでロードマップがツリー構造で返る
- [ ] 各detail項目にscoreとlast_quiz_atが含まれる
- [ ] 中枠のスコアが配下detail項目の平均で算出される
- [ ] 大枠のスコアが配下中枠のスコアの平均で算出される
- [ ] ロードマップ一覧が取得できる
- [ ] 存在しないroadmap_idで404が返る
