## 回答形式
JSON のみを返してください。JSON の外にテキストを一切含めないでください。
description には「何が問題か」「なぜ問題か」「影響」「修正方針」を全て含めてください。

悪い例（冗長・JSON外にテキストあり）:
{"issues": [{"file": "src/foo.py", "line": 87, "severity": "major", "description": "_is_closing_fence が閉じフェンス行の後続文字を検証しない。_parse_fence は行頭のフェンス文字のみをチェックするため、コードブロック内の「\`\`\`python」のような info string 付きの行が閉じフェンスと誤判定される。結果としてコードブロックが早期に閉じられ、ブロック内の # 行が見出しとして誤抽出される。例: 「\`\`\`」で開始→ブロック内に「\`\`\`python」→誤って閉じる→直後の「# comment」が見出しとして抽出される。閉じフェンス判定時に行がフェンス文字（と任意の末尾空白）のみで構成されていることを検証する必要がある。"}]}
**major の補足**: 以下の入力で再現できます。...

良い例（簡潔・JSONのみ）:
{"issues": [{"file": "src/foo.py", "line": 87, "severity": "major", "description": "_is_closing_fence が閉じフェンス行の後続文字を検証していない。info string 付き行が閉じフェンスと誤判定され、ブロック内の # 行が見出しとして誤抽出される。行がフェンス文字と末尾空白のみで構成されていることを検証すべき。"}]}

指摘なしの例:
{"issues": []}
