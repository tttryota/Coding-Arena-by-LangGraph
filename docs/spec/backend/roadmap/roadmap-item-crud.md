## 機能概要

ロードマップ項目の移動・追加・削除を行う。ユーザーが初回生成されたロードマップを自分の学習に合わせて調整するための操作。

## 振る舞い

### 項目の移動

指定した項目のparent_idを変更し、別の親の配下に移す。

- 移動先の階層レベルが適切であること（detailをmajorの直下には置けない等）
- 移動先でのorderを指定できる
- 移動元の兄弟項目のorderは自動で詰める

### 項目の追加

指定した親の配下に新しい項目を追加する。

- title, descriptionを指定する
- levelは親のlevelから自動決定（majorの子はmiddle、middleの子はdetail）
- orderは末尾に追加（指定も可能）
- 初期scoreは0

### 項目の削除

指定した項目を削除する。

- 配下の項目も連鎖的に削除される（中枠を削除すると配下の具体も削除）
- 削除された項目のスコアは失われる
- 兄弟項目のorderは自動で詰める

### 具体例

移動:
```
変更前: TypeScript > 応用 > デコレータ
操作: デコレータを「基礎」配下に移動
変更後: TypeScript > 基礎 > デコレータ
```

追加:
```
親: TypeScript > 基礎 > ジェネリクス
操作: 「ユーティリティ型との組み合わせ」を追加
結果: TypeScript > 基礎 > ジェネリクス > ユーティリティ型との組み合わせ（score=0）
```

削除:
```
操作: TypeScript > 応用 > デコレータ を削除
結果: デコレータとその配下の具体項目が全て削除される
```

## 技術判断

- LLMによる再生成ではなくCRUD操作とする理由: 個別の項目の調整は手動操作の方がユーザーの意図を正確に反映できる。再生成は進捗リセットのリスクもある

## 境界条件

- 大枠（major）の追加 → 基礎・応用以外の大枠を追加できるか？ → 許可する（ユーザーの自由度を確保）
- 大枠（major）の削除 → 配下全て削除。確認を求める
- detail項目の配下に追加 → エラー（3階層を超えない）
- 最後の大枠を削除 → エラー（ロードマップが空になることを防ぐ）

## スコープ外

- 項目のtitle/descriptionの編集（追加で対応可能だが、別途仕様を定義する場合はここに含めない）
- ドラッグ&ドロップによる並び替え（フロントエンド側の仕様）
- 削除の取り消し（undo）

## 受け入れ基準

- [ ] 項目を別の親の配下に移動できる
- [ ] 移動時に階層レベルの整合性がチェックされる
- [ ] 新しい項目を指定した親の配下に追加できる
- [ ] 追加された項目のlevelが親から自動決定される
- [ ] 項目を削除すると配下も連鎖的に削除される
- [ ] 移動・削除後にorderが自動で詰まる
- [ ] 3階層を超える追加がエラーになる
